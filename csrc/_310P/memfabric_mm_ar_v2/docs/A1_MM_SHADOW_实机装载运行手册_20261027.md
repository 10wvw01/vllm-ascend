## 2. 私有装载方案（R2验证、本批复验）

```bash
B=/tmp/opencode/a1-batch            # 私有staging（按批重建，勿覆盖共享安装）
# 顺序不可变：priv-libs(修复版hybm core)→site(插件+V1 device SO)→MF共享lib64→继承CANN/driver
export LD_LIBRARY_PATH=$B/priv-libs:$B/site/vllm_ascend:/usr/local/memfabric_hybrid/1.2.0/aarch64-linux/lib64:$LD_LIBRARY_PATH
# U1系工具另需：PYTHONPATH=$B/site 最前（插件import必须解析到V2_HOST_LIB），再接CANN python路径
```

- **为什么必须显式含site目录**：adapter导出SO的`DT_RUNPATH`在torchrun worker中**不被查询**（LD_DEBUG实证，根因未深究），`libmf310p_device.so`必须经`LD_LIBRARY_PATH`解析。
- **为什么priv-libs必须在最前**：`libmf_smem.so` `DT_NEEDED` `libmf_hybm_core.so`，priv在前才能装载**修复版**（1dc46d7d）而非共享版（88d39285）；`/proc/self/maps`必须出现priv-libs路径——`a1_mm_shadow_arm.verify_patched_stack_mapped()`已fail-closed。
- **campaign会自建同序LD_LIBRARY_PATH**（`a1_mm_shadow_campaign.sh` PREPARE段），launcher只需保证外层env正确。

## 3. 确定性踩坑清单（根因→症状→修复→探测）

### 坑1｜`npu_format_cast(w,29)` NZ物化不保证流有序【数值全错】

- **症状**：进程内首次cast后立即把`w_nz.data_ptr()`交给裸指针Kernel→首个enabled launch输出全错（本批实测 out_absmax≈5 vs ref≈229，双Rank 2/2复现），iter1起全部bit-exact。
- **根因**：NZ物化拷贝对同流裸指针消费者不排队（`aclrtMemcpy`裸读未完成`randn`即返回0佐证）；任何设备同步或格式感知消费后即恢复。
- **修复**：cast后、任何`data_ptr()`消费者前显式`stream.synchronize()`（profile脚本已改）；arm脚本靠`.cpu()`参考隐式同步天然安全。
- **守卫**：UT `test_nz_cast_materialization_sync_guarded`（源码级断言cast→sync→消费顺序）。

### 坑2｜私有修复版Host SO不导出`mf310p_*`池API【sym臂AttributeError】

- **症状**：`ctypes.CDLL(U1_CORE_SO_LIB64)`后`lib.mf310p_create`→`undefined symbol`，双Rank复现。
- **根因**：`mf310p_create`等只编译进**冻结插件**内部（stripped/hidden），任何已安装SO均不导出；冻结身份不可触碰。
- **修复**：`a1_mm_shadow_build.sh`独立编译树内同源V1 adapter（`memfabric310p_adapter.cpp`，默认可见性）→`libmf310p_v1_adapter_export.so`（链接site V1 device SO+共享libmf_smem）；sym臂经manifest校验SHA装载。
- **守卫**：UT `test_sym_arm_uses_manifest_adapter_with_real_loading_gate`。

### 坑3｜工具会话清理会SIGKILL整个进程组【长任务被杀】

- **症状**：nohup+disown启动的campaign/监视器在工具调用会话结束时被静默击杀（STOP_STAGE.json都来不及写）；同一时期setsid启动的监视器存活113分钟。
- **修复**：**一切长任务必须`setsid`启动**：`setsid nohup bash xxx.sh > log 2>&1 < /dev/null & disown`。
- **探测**：`pgrep -af`全名匹配（勿用会漏匹配自身命令行的短pattern）；被杀后campaign可用§4续跑。

### 坑4｜torchrun worker不查DT_RUNPATH

见§2。适配任何带RUNPATH的私有SO装载：**一律进LD_LIBRARY_PATH，不依赖rpath**。

### 坑5｜gitignore `*.log`

evidence目录下log需`git add -f`（本批与R2同法）；`find ... -name "*.log"`批量强加。

### 坑6｜`/tmp/mf_kfc_<pid>_<i>.json`是**旁路标记**不是KFC部署痕迹

旧pid残留≠本轮KFC状态；KFC由首次建池自动部署，KFC旁路env（`MF_KFC_BYPASS`等）一律unset且脚本fail-closed拒绝。

### 坑7｜监视器误杀自身shell

`pkill -f "watch.sh"`会匹配bash工具自身命令行→自杀。停监视器用`pgrep`取pid再`kill $PID`。

## 4. 分批续跑语义（外部占用/被杀后如何续）

**原则（2026-10-27用户指示）**：外部占用类中断**不停整批**，有条件分批续跑；数值/正确性/门禁失败仍硬STOP。已实现于`a1_mm_shadow_campaign.sh`（`695d05769`）：

- 同一OUT目录重跑即续跑：campaign自动校验并跳过已完成的BUILD（manifest身份+产物SHA+HEAD一致）、ROUTE（4份route.json+CSV的SHA/身份）、会话（**与最终分析同源的`read_session`全量校验**：身份/100样本/bit_exact/统计）。
- 部分完成目录自动归档至`OUT/aborted/`（**绝不留在sessions/内**——会破坏assess严格12场目录校验）。
- source SHA跨批次不一致→拒绝混合批次。
- 续跑留痕`RESUME_LOG.txt`；每attempt独立`g0_before_<ts>.txt`快照。
- 续跑前操作者必须：①确认中断原因是外部占用/被杀而非数值错误；②npu-smi复核卡16384干净；③监视器重新运行。
- 本批实例：campaign-run1两次被会话清理击杀，按此语义续跑完成12场；run2为单次不中断干净批次（主结果）。**漂移门禁跨批次不放宽**——run1因native臂场间方差9.7%判INCONCLUSIVE_DRIFT保留为复份，未挑样本。
