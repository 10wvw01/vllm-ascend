## 1. 本轮相对 G1-C 报告的增量结论

### 1.1 单点丢失判别（修正报告 §6.2 的"双丢失"表述）

C2R2 停滞几何（observed）：双 Rank V2 gen208，core0 卡 stage50（chunk 字段
rank0=1、rank1=3），cores1-7 卡 stage60。

由锁步约束判别（derived，`boundary_1024_analysis.json` D-geometry）：

- overlap 流水语义下 rank0 停滞于 k=2 迭代 ⇒ 已投递 signal chunk0-2（3 封）；
  rank1 停滞于收尾等待 ⇒ 已投递 chunk0-3（4 封）。
- 终态 reqSeq 1025/1026 = 基线 1022 + 3/4（唯一自洽解；非 overlap 假设矛盾）。
- **rank1 等待的 chunk3 邮件从未被 rank0 投递**（rank0 卡在 k=2，未到 k=3 的 signal）
  ⇒ 该等待是停滞的**下游结果，非第二封丢失**。
- 唯一无法解释的等待：**rank0 等 rank1 的 chunk1 邮件**——该邮件的 signal
  （dev1 请求环 seq 1023）已被 AICPU 消费（环排空）、SQE 三连已被 CP 消费
  （SQ 空、hwHead=hwTail），但到达戳始终未在 dev0 的等待槽出现。

### 1.2 1024 边界精确对齐（derived，算术锁定）

源码常量（observed from source）：`ARR_SLOTS = SQ 深度 = 1024`，每邮件 3 SQE，
到达戳 1 基。⇒ **seq ≡ 1023 (mod 1024) 的邮件同时占据 ARR 末槽(1023) 与 SQ 末槽
(1023)——两环边界被算术锁定，无法分别归因**。

C2R2 丢失邮件（D-loss）：

| 属性 | 值 |
|---|---|
| 等待方 / 源方 | rank0（dev0 ARR 环）/ rank1（dev1 请求环 seq=1023） |
| 到达槽（等待方） | **ARR[1023]（环末槽）**，期望戳 1024 |
| SQE 链（源方） | SQ 槽 1021→1022→**1023（环末槽）** |
| 同代前一封 | chunk0 seq=1022 → ARR[1022]，**已到达**（rank0 通过 prev=0） |
| 同代下一封 | chunk2 seq=1024 → **wrap 邮件 ARR[0]**，在**反方向**（dev0→dev1）健康到达（rank1 通过 prev=2 证明） |

即：同一停滞代内，槽 1022 正常、槽 0（wrap）正常（反方向）、**槽 1023 丢失**。

| B02 | 6146/6145（差 1） | 1/0 | **1023（同构推断）** | 第 6 次 wrap 后 1-2 封 |

两次失败均以"双设备游标停在边界后 0-1 封、±1 不对称"收场，几何同构
（3/4 signal 不对称 ⇒ ±1 游标差）。若丢失位置与环位无关，两次均落在边界区间
（±1 封，2/1024 窗口）的概率量级 ~1e-5。**统计显著但 n=2，且 B02 槽位依赖同构
假设（无 V2 戳直证）；不构成根因结论。**

## 2. 假设空间更新（供复核判别；均为候选，无排他证据）

丢失发生在"CP 已消费 SQE#2（到达戳 8B 跨 die 写：dev1 SDMA → dev0 ARR_STAMP[1023]）"
与"dev0 AICore dcci 轮询未见到达戳"之间。候选机制：

| ID | 机制 | 与观测的相容性 |
|---|---|---|
| C-a | SQE#2 的 8B 跨 die 写静默丢失（未落 dev0 GM） | 相容：槽值保持 0（C2R2 首圈）/旧值（B02 第 6 圈），均 < expect ⇒ 无限轮询挂起 ✓ |
| C-b | SQE#2 目的地址在边界条件下算错（写到别处） | 相容（同上表现）；需解释为何仅 seq≡1023 触发 |
| C-c | AICPU 对 ARR_MAIL[1023] 的预写（SQE#2 的 8B 源）丢失/陈旧 ⇒ 戳值错误 | 相容；若戳值写了但 ≠1024 且 <1024 仍挂起；若 >1024 应走 OVERRUN（未观测到） |
| C-d | 写入落地但跨 die 可见性异常（AICore dcci 仍读旧值） | 相容但较弱：dcci 每次轮询均失效缓存，需 die 间一致性缺陷才成立 |
| C-e | 等待方 ARR_HEAD 更新丢失（上一封消费后 head 未推进） | **不相容**：会立即匹配旧槽戳并重复消费/校验失败走 trap，非挂起 |
| C-f | SQ 容量/Head 异常（H1 复活） | **已被设备侧直接证据反驳**（SQ 空、hwHead==hwTail、rc=0） |

排除项维持：H2（Epoch）设备侧反驳再确认（纪 6-9 正常轮转）；H4 收窄为下游表现。

## 3. G1-D 最小取证候选探针（提案，判定与取舍归复核方）

按"最小侵入、只读、可判别 C-a/b/c/d"排序：

1. **停滞时到达环邻域转储**（512B 级 D2H，读 dev0 保留区）：
   ARR_STAMP[1020..1023] + ARR_STAMP[0..2] + ARR_MAIL[1023]（f0-f3）+ ARR_HEAD 游标。
   判别力：ARR_MAIL[1023] 内容正确而 ARR_STAMP[1023]≠1024 ⇒ 定位到 SQE#2 单点
   （C-a/C-b vs C-c）；ARR_MAIL[1023] 也错 ⇒ AICPU 预写链（C-c）。
2. **源方 quiet 环转储**（dev1 保留区 512B，64 槽 × 8B）：quiet[63]（seq1023）
   应=1024、quiet[0]（seq1024）应=1025、quiet[1]（seq1025）应=1026。
   判别力：quiet 戳在 ⇒ SQE#3 已执行 ⇒ 链越过了 SQE#2（丢失收窄到 SQE#2 单点）；
   不在 ⇒ 链在 SQE#2/#3 之间中断（与 SQ 游标越过矛盾，本身即强证据）。
3. **[MF_G1C] 扩展字段**（v13 设备库）：把 quiet 环末 4 槽 + ARR_HEAD 纳入 1Hz 快照
   （仍 64B 内或扩至 128B，需评审），避免依赖停滞时刻的人工转储。
4. **边界加速复现实验**（需复核方设计）：在受控单测里把请求环预填至 seq≡1020-1023
   再发起交换，观测丢失是否随边界位置复现——判别"边界相关"是否为因果而非巧合。
   注意：此实验改变时序，不能与生产复现率混算。
5. **双 Rank 同代 V2 stage 对齐转储**：C2R2 已证明 1Hz 采样足够定位停滞代；
   如复核方需要 per-chunk 粒度，可评估 stage 字扩展 chunk 序号（需动诊断区布局，评审定）。

约束提醒（沿用 G1-C 红线）：只读取证；不改 MM/通信/SQE/Mailbox/IB/Epoch/KFC 算法；
新设备库必须独立 KVER（v13）；原 v11/现网库与历史证据不可覆盖；测试后恢复并核对
SHA256；证据不足处标 UNKNOWN。
