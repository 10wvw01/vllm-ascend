### 3.2 已实测事实

1. **块数碎片化单调变慢**（O1 下，M2048：2→4→8 块为 1356.7→1600.7→1840.8；M4096：4→8→16 块为 2530.7→2904.6→3423.4）：每倍增块数的代价 M2048 约 +240us、M4096 约 +374~519us。
2. **Overlap=1 一致优于 Overlap=0**（同 M 同 Chunk 全部 6 对成立）：节省量随块数增长——M2048 C1024 −343us / C512 −481us / C256 −1005us；M4096 C1024 −605us / C512 −1057us / C256 −1862us。
3. **两效应方向相反、净效应为负**：重叠节省随块数增长的幅度小于块碎片化带来的开销增长，故 C256/512 的 O1 仍全面落后 C1024/O1。
4. **M 伸缩近线性**：C1024/O1 下 M2048→4096 为 1356.7→2530.7（×1.87，略低于 2×，符合固定协议开销随块数摊薄方向）。
5. **零长尾**：全场次 max 配对 event 5484.7us < 6ms 停顿线；p99−p50 包络 ≤ 261us（17 场）。
6. **Wall 与 Event 一致**：wall p50 − event p50 ≈ +50~95us（launch+sync 主机开销），两口径排序完全一致。

### 3.3 关键路径归因边界（假设，未逐段证实）

网格数据只能证明"总时长随块数增加而上升、随重叠开启而下降"。**本轮没有设备时间线证据，不虚构 MM/SDMA/IB/signal-wait/Add 各阶段的耗时贡献。** 与数据相容且优先级最高的两个候选解释（下一轮若做 F2-2 时间线取证再验证）：

- **假设 H1（块数→握手开销）**：每增加一个 Chunk 引发一对 signal_at/wait_at 与 IB 邮件、以及 per-chunk CleanLines/失效，固定开销 × 块数主导恶化——与 F2 计划 §4.2 的预判一致；
- **假设 H2（小块 MM 效率）**：C256/C512 的 per-chunk MM 规模小于 Cube 阵列高效区间，MM 本身变慢。两假设可通过 C1024/O1 与 C512/O1 的双 Rank 时间线（Core0 signal/对端邮件/Add 的真实等待空档）区分。

### 3.4 锚漂移

- M2048 基线锚 4 场：1288.8（s01）/1356.8/1356.6/1366.5——**首场比后三场均值快 5.0%**，后三场离散仅 ±0.4%。s01 紧接 G0 同形状试运行（热池刚销毁重建、设备缓存热），属热态首场效应。
- M4096 基线锚 4 场：2499.0（s10）/2539.2/2531.1/2530.2——首场快 1.3%，后三场 ±0.2%。
- 结论：**同 M 组内后三锚高度稳定，首锚偏快需在跨场次比较时计权**；本轮所有候选场均夹在后三锚之间/之后执行，组间对比不受该漂移影响方向性结论（所有候选落后幅度 ≥12.9%，远超 5% 漂移上界）。
