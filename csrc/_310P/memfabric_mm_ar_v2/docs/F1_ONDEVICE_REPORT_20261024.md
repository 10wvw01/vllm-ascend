## 3. 分析

### 3.1 已实测事实

1. **融合路径成本对小 M 不敏感**：M=1→64 全网格中位 0.335~0.360ms（离群行除外），平坦；64 倍 M 增长无对应耗时增长——**固定开销主导**，与 F1 计划对 MM/IB/signal/wait/SDMA/Add/DONE 固定成本的预判一致。
2. **Stock 侧同样平坦**（0.387~0.433ms）：Stock 的 HCCL AR + launch 固定成本主导；注意本驱动的 Stock 路径含 `.float()/.to(half)` 两次逐元素转换（T1 驱动历史口径，两侧一致沿用，不影响组内比较，但影响与外部数字的绝对可比性）。
3. **M=10 最优配置 MM=8**：MM=8 三组（0.344/0.340/0.343）一致优于 MM=4 三组（0.357/0.355/0.353），Δ≈3.5~4%；M=8/16 同方向；M=32/64 反向（MM=4 略优）。**Add 核数 1/4/8 在所有 M 下无稳定差异**（±0.005ms 量级）——Add 分核不是有效优化维度。
4. **长尾形态**：多数组 p95≈0.49~0.52ms（约 +0.15ms 台阶），少数组 p95≈0.35~0.37ms；说明存在间歇性 host/设备干扰（怀疑与 AICPU 编排核 100ms 心跳纪元或 host 调度相关，未取证，不下结论）。
5. **首次调用**（首写保护路径）0.268~0.630ms 散布，无组间规律，与 D4 以来已知首写设备级同步语义一致。

### 3.2 固定成本拆解边界（不虚构）

本初筛只有一个总时长口径（host sync 包住 launch+kernel+sync），**没有 MM/IB/signal/wait/SDMA/Add/DONE 各阶段的独立计时**。以下仅为与数据相容的假设，供 F1-2 设计，非实测贡献：

- H1：融合侧 ~0.34ms 中 MM 计算占小头（M≤64 的 FLOPs 极小），大头是 launch + 协议握手（signal/wait/邮件校验/quiet/DONE）+ host sync；
- H2：MM=8 优于 MM=4（M=8~16）的解释候选是 N-split 并行度收益超过核间 IB 等待代价；M=32/64 反转则指向 IB 等待随参与核数增长——需 F1-A（MM 隔离）与 F1-B（协议探针）区分；
- H3：Add 核数无差异 → Add 调度/执行不在 M≤64 的关键路径敏感点上。

### 3.4 离群行与环境事件（如实披露）

1. **(16, MM4, Add1) 中位 0.450ms、(64, MM8, Add4) 中位 0.485ms**：同组兄弟行均 0.335~0.353ms。两行正确性无损（30 次全位精确、status=0）。成因未取证；怀疑与并发 stdout 干扰源（§6.2 的 `..` 写入器）或 host 抖动同期。**不删除、不重跑**，F1-C 复测时观察是否复现。
2. **stdout 并发噪声**：会话日志中两处行首出现无换行 `..` 前缀（其一命中矩阵行 (16,4,1)），经最小分析器容错修复后完整解析 36/36（`noise_prefix_rows:1` 留痕于 JSON）。原始日志未修改。

## 4. 裁决与下一轮建议

### 4.1 当前裁决

- **SCREEN_ONLY**：M=10 及邻近形状的初筛方向性信号为正（融合更快），但**不得据此宣称 MemFabric 融合在 M=10 严格胜出 Stock**（建池前/后 + host sync 口径偏差，F1 计划 §2 明文约束）。
- 分核初筛结论（可沿用）：**M=10 候选配置 MM=8/Add=4（或 Add=1，无差异）**。
- 正式 Kernel、协议、Stock 默认零改动。

### 4.2 下一轮（F1-2）单变量/取证优先级

1. **F1-C 同场严格对照（最优先）**：同一进程、同一池、M=10：T1 融合 vs Stock F.linear+HCCL（去 fp32 转换的纯 fp16 路径 + 现行口径各测一遍），双 Rank NPU Event 配对（`max(r0,r1)`）+ ABBA≥2 轮，无 Profiler。这是关闭"谁在 M=10 真快"的唯一途径。
2. **F1-B 协议固定成本探针**：AR-only / signal-wait 循环探针量化单次握手成本（现有 `mf310p_v2_trial_run_ar_only` ABI 已在位），回答"协议下限是否已接近/超过 Stock 总时长"（F1 计划 §三 技术取舍前置判据）。
3. **F1-A MM 隔离**：M=10 纯 MM（NZ）核数 4/8 对比，量化 MM 侧占比（验证 H2）。
4. 观察项：p95 ~0.5ms 台阶的来源（epoch 心跳 vs host 抖动）——若 F1-C 的 Event 口径下 p95 台阶消失，则归因 host sync 侧。

### 4.3 真实模型验收前置（不变）

若 F1-C 出现稳定显著胜出，才进入真实 Qwen3.6 三方对比，配置严格固定：**输入 4096、输出 2048、TP=2、batch 上限 10、Eager**，并留存实际步内 batch 证据；不混用历史输出 512 数据。
