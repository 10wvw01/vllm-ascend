# G1-C 首停点分级诊断设计（研发审查稿）

> 基线：vllm-ascend `diag/310p3-gate-e-forensics-20261020 @8f1eef3b`、MemFabric `diag/310p3-gate-e-forensics-20261020 @eb96eced`；服务器实际原版运行库应已恢复为 SHA256 `88d39285...`，KVER=11。G1-B B02 原始证据仍在服务器 `tmp/opencode/gate_e_forensics/B02/`。

## 1. 设计决策

**可以开始 G1-C 研发，不应立即部署尚未开发的设备追踪版本。** 先做离线收敛 + 观测可行性验证，优先只修改 vllm-ascend 诊断 Kernel。只有第一层已证明 Core0 卡在 SDMA 流程且仍无法判因，才引入 MemFabric AICPU KVER=12 独立诊断二进制。

G1-B 事实：B02 第 29 个完成请求之后出现双 Rank 31ms 间隔的 507014；50 个已完成 Epoch 正常、ReqRing 最大瞬态 pending=1、没有观测到连续积压；最后一纪仍运行。**不得等价推导“硬件 SQ 永不满”或“SDMA 已全部完成”**。

代码约束：
- `consumeOneMail` 在 `flushBatchDoorbell` 之前推进 `ReqHead`。请求环已消费不等于 SQ Doorbell 已敲响，更不等于 SDMA 数据/戳写回。
- `SqContext.sqHead` 仅在 Epoch 起点获取，`submitSqe` 的满环检测对合法模游标不会触发；纪末 `headAfter` 是稀疏快照，而非全过程占用曲线。该源码缺陷依旧存在，但与 Gate E 的因果尚未证实。
- V2 `mf310p_v2_trial_run` 每次 `aclrtMemsetAsync(status)`，且 `CheckOrTrap` 只在失败时写同一个 64B 状态；该区域不适合作为多层异步波的最终进度证据。
- B02 在 slog 静默之后仍有 Epoch 正常退出和消息消费，**slog 无输出不是 AICPU 已停摆的证据**。
- “29 个完成请求”是 vLLM Bench HTTP 请求统计，不是 V2 Kernel launch 数；先核对两次失败的真实 V2 波序列与形状，不能认为恰好第 29 次融合波必挂。

## 3. G1-C1：单变量实验，优先 V2 Kernel 阶段追踪

仅改 vllm-ascend 专用诊断构建；MemFabric Host/AICPU、KVER11、Mailbox wire/Tag/SQ 协议保持不变。

### 3.1 跟踪状态设计

- 每 Rank 分配**独立、常驻**的 GM 诊断缓冲区；每核独占至少 64B 缓存行，禁止共享写入或与现有 `status`/IB workspace 混用。
- 每个记录包含：`magic/version`、`launch_seq`（本 Rank 单调递增、可对应 Host 提交日志）、`core_id`、`phase`、`chunk_id`、`phase_counter`。Host 另外记 `rank`、`M/chunk_rows`、`layer_id` 或调用点、`stream`、槽号 `output_slot`、提交时刻和结果状态。
- 设备 Kernel 进入时重写本核记录并更新 `launch_seq`，防止上一波残留进度误判成本波。记录只要求找到**最新已执行波**，不依赖所有历史事件永久留在 GM；Host 低频保留最近数波提交元数据。
- Core0 标记（进/出成对）：`MM`、`WaitReady`、`signal`、`wait`、`ReleaseAdd/Add`、`WaitAddDone`、`quiet`、`DONE signal/wait`、`kernel exit`。
- Core1–7 最少标记：`MM enter/exit`、`IB Ready submit`、`IB Add release enter/exit`、`Add exit`、`IB Done submit`、`kernel exit`。
- 所有可能无限等候的 `IBWait`、`smem_shm_sdma_wait_at`、`quiet_at` 在**进入前**写回阶段戳；不得依赖退出时或 `Trap` 才留证据。阶段值定义为协议常量，双方不可各自硬编码一份漂移的映射。
- AscendC 写 GM 后按既有 `CleanLines` 纪律刷写独立缓存行；不开设备 printf；正式构建默认关闭。只允许改内部 Kernel launcher 传参和诊断上下文，不修改对外 Torch Op 或 C API 的签名，不修改模型数值和 SDMA 语义。

### 3.2 观察通道必须先做可行性 Gate

**先在可退出的短时试验 Kernel 下验证阶段槽的可观测性，再跑 Qwen。** 要验证：
1. Core0 运行且有其他 Core 等待时，Host 是否能在**不全设备同步**的前提下读取新的 GM 进度；跨线程必须正确设置设备/context。
2. 独立 Host 观察者 1Hz 读取的 ACL API 是否可能阻塞在计算流上；如果读取会被同一流拖住，改方案，不准把“死后自动读取成功”写成设计前提。
3. 每秒把**已取得的快照**持久化到本地独立文件（不写 Public Git），使 Worker 异常退出时仍能保留最后一次成功快照；进程退出后 GM 可能释放，不能只靠退出清理钩子。
4. 诊断开启前后 T0/Gate B 小矩阵位精确、Trace 数据真实前进，且没有额外的 AICore 同步或跨 Rank barrier；统计是否引入不可接受的性能/时序扰动。先至少 1 次短时 Stock/Fused 功能烟测；判据记录而不伪造性能结果。

如 **读取不可靠**：先解决“如何保留快照”，而不是继续加诊断字段和运行长稳。

### 3.3 一轮故障如何区分

| 双 Rank 的最后可信阶段 | 优先解释 | 下一个实验 |
|---|---|---|
| 多 Core 停在 MM 或 MM 未返回 | MM/输出 GM 写回/计算核资源问题 | 核查矩阵形状、执行流、缓冲地址；不是先改 SQ |
| Core0 停在 WaitReady，其他 Core 未到 Ready | 单核 MM/IB 到达不齐 | IB/其他核详细埋点 |
| Core0 `signal` 进入但未退出 | AICore 请求环背压/缓存可见性或设备异常 | 查请求游标及 Core0 cache |
| Core0 `wait` 已进入，未返回 | 对端消息缺失、SDMA 未完成、Mailbox 戳异常或对端未投递 | 进入 G1-C2 设备 SQ/Stamp 诊断 |
| Core0 `quiet` 或 DONE 等待 | SDMA quiet 戳或双 Rank 完成握手异常 | 进入 G1-C2，有针对性采集 |
| 两 Rank V2 均正常退出而随后 Stock 挂 | 非 V2 波内停顿，优先查算子/Stream 依赖、输出槽生命期及跨流竞争 | 增补 Host stream/event/slot 时序，无需先改 AICPU |

“最后阶段”必须以 `launch_seq`、Core0/其他核、双 Rank 同一波调用对齐，并结合 Host 上次成功快照时间判读；不可把最后一条 Host 错误日志当作第一故障点。

## 4. G1-C2：只有 C1 将停顿收敛到 SDMA 后才引入

由方案负责人另起 MemFabric **设备诊断分支**，新设备侧产物版本（例如 KVER=12，只用于诊断、不可覆盖 11）；不改既有 Mailbox 布局/ABI，若必须扩展 Host↔AICPU 内部 Param 应成对更新、单独验证；每封 SQE 的 3 连发送语义保持一致。

采集：当前纪内实际 SQ Head/Tail/Depth 的查询值和返回码、每封 3 SQE 写入位置、每批 Doorbell 的新 Tail 与成功码、ReqHead 更新进度、到达/完成戳是否推进。重点关注 **ReqHead 早于 Doorbell**、**SQ shadow Head 不更新**、SQ 游标环绕与瞬时覆写的可能性。不得只用 Epoch 尾部 `headAfter` 代替实时采样。

仍要满足：异常时独立快照可读、正常运行阶段最小开销、故障前后双 Rank 可对齐；启用前在最小 SDMA 正确性及 Epoch 跨纪回归通过。

## 5. 实机执行准入及停止条件

- Git 仓库和生产 SO 的版本追溯可复现，当前无遗留 G1-B 日志注入/诊断库；独立工作树，历史证据与原库备份保持原状。
- 设备 0/1 协调独占窗口，禁止与其他租户并跑；发生故障保留现场，不自动重装、清空或强杀外部任务。
- 首先 CPU 静态检查 → CANN 构建 → T0/最小 TP2 位精确 → 可观测性 Gate → 5min 短诊断 → 原 Gate E 620s / 必要重复。某个 Gate 失败时**立即停止升级**，不继续扩大埋点或猜测修复。
- 本阶段 **不修通信算法**；只交付可靠的“Rank / wave / Core / chunk / stage”第一停止点，或有证据地陈述哪一层仍不可区分。
- 新实验默认使用独立 `tmp/opencode/gate_e_forensics/G1C_*/` 目录、完整哈希/日志，禁止把本地证据文件直接推到 Public GitHub；代码和经脱敏的结论报告单独提交。
