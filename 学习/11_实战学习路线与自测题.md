这章不是继续增加概念，而是告诉你怎样练到真正能独立处理这个项目。


```text

```

不要急着背函数名。

## 5. 第五阶段：第一次真正读 AscendC

只读 `Mf310pDirectProducerKernel`。

不要先研究所有模板宏。

逐行标注：

```text

A/B/C address
Matmul
cache clean
ready

signal
```

然后自己画 q=1：

```text
256 rows
core0: row 0..31
core1: row 32..63
...
core7: row 224..255
```

### 过关标准

你能准确回答：

> Decode Split-K 和这里的 8-core M-split 是不是同一个概念？

答案：不是。这里是在一个固定 projection MM 中显式按 M 分工，目的是 8 AI Core 合作产出同一 communication batch；不是 vLLM Decode attention 的 Split-K 机制。

## 6. 第六阶段：自己证明同步协议正确

用最极端的问题逼自己理解：

### 问题 A

删掉 ready 会怎样？

应答：core0 可能在其它 core C 未完成前 signal，peer 得到半新半旧 output。

### 问题 B

ready 放到 cache clean 前会怎样？

应答：ready 不能再证明 SDMA 可见性，存在读旧缓存数据风险。

### 问题 C

删掉 credit 会怎样？

应答：下一 wave 可能覆盖 peer 仍在消费的 arena。

### 问题 D

每 batch 都 quiet 呢？

正确但可能破坏流水，性能下降。

### 过关标准

能把机制分成：

```text
必须有，否则错
可以替代实现，但当前这样更快
纯性能策略
```

---

## 7. 第七阶段：研究 small-M 为什么改 N-split

先不用跑代码，做纸面比较。

### M-split，M=16

8 core 分 16 行，每 core 只有约 2 行，但每核仍要消费完整大 B。

### N-split

8 core 每核处理 16/T 行，但只消费 256 列权重 slice。

然后看源码注释里的实机测量背景。

### 实验建议

测：

```text
M=1,2,4,8,16,32,64,128,255
small path ON/OFF
```

记录：

```text
latency
AI Core MM
SDMA
add
```

### 过关标准

你能用“权重流固定成本”而不是“因为代码这么写”解释 N-split。

## 8. 第八阶段：独立复现 q 实验

矩阵：

```text
q=1/2/4
M=255/256/257
M=511/512/513
M=1023/1024/1025
以及真实 serving 高频 M
```

为什么一定测边界？

因为：

```text
一个 token 的变化
可能让 batch 数 +1
或者从 small path 切到 batch path
```

平均点可能看不出真正回归。

### 过关标准

最后不要说：

```text

```

而应该说：

```text

在真实 M histogram 加权后，当前 workload 推荐 ...；
主要原因从 profiler 看是 ...
```

## 11. 推荐的 correctness 测试阶梯

每次改融合核心，不要直接跑 10 分钟大模型。

按风险逐步放大：

```text
1. build / link
2. feature-off 不影响普通构建
3. feature-on custom op 可解析
4. 两 rank 最小 correctness
5. M=255/256/257
6. q=1/2/4
7. small-M 全阶梯
8. random M 矩阵
9. repeated 1000+ waves
10. eager profiler
11. Qwen 模型短请求
12. ACL Graph
13. DFlash 组合
14. 长稳运行
```

这个顺序的原则是：

> 先便宜地抓确定性 bug，再进入昂贵端到端场景。

---

## 12. 每次改协议至少检查这些不变量

```text
[ ] TP rank 只有 0/1
[ ] 两 rank 对 q/batch_m 理解一致
[ ] 每个 producer batch 只 signal 一次
[ ] signal 前 8 core 数据都可见
[ ] wait 校验 dst/len/imm
[ ] add 只消费 valid_rows
[ ] wave 结束前不复用 arena
[ ] graph capture 内无动态首次初始化
[ ] failure 后不继续复用 poisoned protocol
[ ] shutdown 不提前 free in-flight memory
```

把它当 code review checklist。

## 14. 最终能力阶梯

### Level 1：会跑

知道怎么启动模型、打开 feature。

### Level 2：会看

能追 Python route 和设备 op。

### Level 3：会解释

能解释为什么这样设计。

### Level 4：会排障

能从 runner → runtime → protocol → kernel 定位错数/死锁。

### Level 5：会优化

能从 profiler 提出可证伪实验，而不是盲改。

### Level 6：会演进

能判断下一项能力应该：

```text
扩合同
换并行切分
改通信算法
做高层融合
还是根本不该继续优化这里
```

这个目录的目标不是让你停在 Level 2，而是走到 Level 5~6。
