# 12｜术语表：给第一次学 vLLM / 昇腾 / 融合算子的你

这份术语表不追求教科书定义，先用“在本项目里它是什么意思”解释。

## A

### ABI

Application Binary Interface，二进制接口合同。

在本项目里 `memfabric310p_adapter_api.h` 的 ABI v7 约定：

```text
函数名
参数类型
结构体布局
版本号
```

vLLM Runtime 和 MemFabric adapter 都按这个合同编译，才能正确协作。

### ACL / aclrt

Ascend Computing Language Runtime 相关 host API。

本项目里常见：

```text
aclrtMalloc
aclrtMemcpyAsync
aclrtMemsetAsync
aclrtSynchronizeStream
```

负责设备内存、拷贝、stream 等运行时操作。

### AI Core

昇腾芯片上执行高性能计算 kernel 的核心。

本次 MM producer 使用 8 个 AI Core/block 协作。

### AllReduce

多个 rank 各有一份 tensor，做 reduce 后每个 rank 都拿到最终结果。

本项目 TP=2、SUM：

```text
rank0: Y0
rank1: Y1
最终两边都得到 Y0+Y1
```

### Arena

提前分配的一大块可循环复用内存区域。

当前 MemFabric runtime 有 send/recv arena，避免每轮动态 malloc，并支持 batch pipeline。

---

## B

### baseM

当前 MM+AR 的基础 M 粒度：

```text
baseM = 256
```

通信 batch：

```text
batch_m = baseM * q
```

### Batch

在不同语境有不同含义。

vLLM serving 里可能指一轮一起推进的请求/token；MM+AR runtime 里特指一次 producer/communication 的 `batch_m` 行。

看到“batch”一定先确认上下文。

### BF16

BFloat16，一种 16-bit 浮点格式。当前 MM+AR 合同要求 FP16，不接受 BF16。

### Block Table

vLLM 用来把逻辑 token block 映射到物理 KV Cache block 的表。

DFlash/310P 中它和 slot mapping、physical block size 密切相关。

---

## C

### CANN

昇腾软件栈。可以把它粗略理解为 CUDA 生态在昇腾上的对应基础设施集合，包括编译、运行时、算子、profiling 等能力。

### Cache Clean / Invalidate

让 AI Core 写入缓存中的数据按需要回到对其它 engine 可见的内存状态，并处理缓存一致性。

本项目 producer 在发布 ready 前清理自己写的 C 区域，确保 SDMA 不读旧数据。

### Continuous Batching

vLLM 不是固定一批请求从头跑到尾，而是活跃请求可以每轮动态加入/退出。

### Credit

一种资源使用许可。

当前 MM+AR 中 wave credit 用来保证：下一波不能过早复用 peer 仍在消费的 arena。

### Custom Op

自定义 PyTorch 算子。

本项目 Python 调：

```text
torch.ops._C_ascend.memfabric_mm_ar_allreduce
```

真正进入 C++/AscendC 自定义实现。

---

## D

### Decode

模型生成阶段。每轮基于已有上下文继续产生新 token。

普通 decode 单请求每轮新增 token 少，因此 small-M 性能很重要。

### DFlash

仓库支持的一种 speculative decoding proposer/方案。

对学习本项目，先把它理解成：便宜的 draft 路径提出多个候选，target 一次验证，尽量一次推进多个 token。

### Draft Model / Draft Proposer

投机推理中负责“先猜未来 token”的便宜模型/模块。

### DSpark

仓库中的另一类 speculative proposer。与 DFlash 类似属于投机推理体系，但具体算法/实现不同。

---

## E

### Eager

不依赖预录 Graph，每轮由 host 正常发起执行。

本项目 eager MM+AR 使用递增 generation，避免每 wave 清 ready cells。

### EP

Expert Parallel，MoE 中把不同 expert 分布到不同设备的并行方式。

和本项目 TP=2 o_proj 的 Tensor Parallel 是不同并行维度。

---

## F

### FP16

IEEE half precision，16-bit 浮点。

当前 MM+AR 的 activation、weight、partial output、通信 payload、local add 都按 FP16 合同处理。

### FRACTAL_NZ / NZ

昇腾矩阵单元偏好的分块权重布局之一。

当前 producer：

```text
A: ND
B: NZ
C: ND
```

格式变化不改变数学，只改变内存排布。

### Full Attention

标准的全注意力层类型。本项目对应目标 projection：

```text
self_attn.o_proj
```

---

## G

### GDN

当前 Qwen 模型族里 linear attention/recurrent 相关路径的一部分。学习本项目时重点知道：它也有输出 projection `linear_attn.out_proj`，当前 shape/TP 合同与 full-attention `o_proj` 相同，所以可以复用 MM+AR。

### Generation（ready generation）

不是“文本生成”的 generation，而是 ready cell 的版本号。

用于区分不同 wave，避免把上一轮 stale ready 当成本轮完成。

### GM

Global Memory，设备全局内存。AscendC kernel 的输入/输出通常通过 GM tensor 访问。

### Graph / ACL Graph

预先捕获一组稳定设备操作，后续 replay，减少 host dispatch 开销。

代价是动态初始化/malloc/shape 更受限制。

---

## H

### HCCL

Huawei Collective Communication Library。

普通 TP 路径常用它做 AllReduce。当前定制 MM+AR 在目标层绕过通用 HCCL AllReduce，使用 MemFabric peer exchange + local add 实现 TP=2 SUM 语义。

### Hidden State

Transformer 层之间传递的 token 特征向量。

可以简单理解为每个 token 当前“内部表示”。

---

## I

### INT8

8-bit integer。W8A8 模型大部分量化 Linear 可能使用 INT8 相关计算，但当前融合 projection 是被跳过量化的 FP16 层。

### ITL

Inter-Token Latency，连续输出 token 之间的延迟。Decode 服务体验的重要指标。

---

## K

### K（矩阵维度）

在矩阵乘：

```text
[M,K] @ [K,N] -> [M,N]
```

K 是 reduction dimension。

本次 TP=2 后 local K=2048。

### K（speculative tokens）

在投机推理语境里又常表示一次 draft 猜多少 token。

例如当前 310P DFlash 最多 15 个。

同一个字母不同语境含义完全不同。

### Kernel

设备上执行的函数，例如：

```text
Mf310pDirectProducerKernel
mf310pWaitBatchKernel
mf310pAddKernel
```

### KV Cache

Attention 保存历史 Key/Value 的缓存。

Decode 不需要每次重算所有历史 token，是大模型高效生成的基础。

---

## L

### Layer Prefix

框架中标识模型参数/层路径的字符串，例如：

```text
model.layers.3.self_attn.o_proj
```

当前融合会从 prefix 提取 layer index 和后缀，再交叉检查真实 layer type。

### Linear Method

vLLM/vLLM-Ascend Linear 层真正执行权重加载和计算的策略对象。

本项目关键类：

```text
AscendUnquantizedLinearMethod
MemFabricMmArLinearMethod310
```

### Lookahead

当前 MM+AR pipeline 的“提前排下一份工作”深度。

lookahead=1 的核心顺序：

```text
P(n+1) 在 W/A(n) 前排队
```

目的是让 SDMA(n) 与 MM(n+1) 重叠。

---

## M

### M（矩阵维度）

```text
[M,K] @ [K,N]
```

M 是一次一起处理的行/token 数。

在 serving 中它不是简单等于用户并发数。

### MatMul / MM

矩阵乘法。当前融合名字里的 MM 就是 output projection 的矩阵乘。

### MemFabric

本项目使用的 310P 定制通信/共享内存能力。

vLLM 只依赖其 public SHM/SDMA 接口，不应依赖私有 transport 内部布局。

### MoE

Mixture of Experts。通过 router 让 token 只进入部分 expert，从而用较低激活计算量承载更大的参数规模。

### mRoPE

更复杂的 Rotary Position Embedding 位置编码形式。DFlash 一次构造多个 speculative position 时需要专门正确生成。

---

## N

### N（矩阵维度）

输出列数：

```text
[M,K] @ [K,N] -> [M,N]
```

当前 MM+AR N=2048。

### ND

普通 dense/二维逻辑布局。和 NZ 这类硬件分块格式相对。

### N-split

按输出 N 维给多个 core 分工。

当前 small-M path：

```text
N=2048 -> 8 × 256 columns
```

每 core 只读取自己的权重 slice。

---

## O

### o_proj / out_proj

Attention/Linear Attention 最后的 output projection Linear。

当前融合目标：

```text
self_attn.o_proj
linear_attn.out_proj
```

### Op Fusion

算子融合。不要狭义理解成“最后只剩一个 kernel”。

当前 MM+AR 是系统执行边界融合：上层一个 op 统一拥有 MM、通信、规约和 pipeline，但内部仍可使用多个设备 kernel。

---

## P

### Padding

为了固定 kernel shape，把实际 M 补到更大的模板大小。

无效行只要不会进入最终结果，数学仍正确，但会浪费计算。

### Patch

运行时替换上游某些类/方法的实现，使 310P 能复用通用框架协议又采用平台特化代码。

### Prefill

先处理 prompt、建立 KV Cache 的阶段。通常 M 较大，和 Decode 的性能形态不同。

### PrivateUse1

PyTorch 给第三方设备后端保留的 dispatch key 机制。vLLM-Ascend custom op 可通过它把 NPU tensor 调度到对应 C++ 实现。

### Producer

本项目 MM+AR 里负责：

```text
MM -> cache clean -> ready -> signal
```

的设备路径。

### Proposer

Speculative decoding 中提出候选 token 的模块。

---

## Q

### q / `batch_basem_count`

当前 MM+AR 通信/计算 batch 是多少个 baseM：

```text
q ∈ {1,2,4}
batch_m = 256*q
```

当前默认 q=1。

### quiet

MemFabric device 操作，用于确保本地 outbound SDMA 在 wave 尾部完成/drain。

不等于等待一封 peer mail。

---

## R

### Rank

分布式进程/设备编号。

当前融合固定 TP=2：

```text
rank 0
rank 1
```

### ready cell

每个 batch、每个 AI Core 的完成单元。

core 写入当前 generation，core0 等 8 个都 ready 后才能 signal。

### Reduce

把多个贡献合成一个结果。当前是元素级 SUM。

### `reduce_results`

`RowParallelLinear` 控制是否在 Linear partial output 后执行通用 TP reduction 的标志。

融合 path 已经自己 reduce，因此必须设为 False。

### RoPE

Rotary Position Embedding，用旋转方式把 token 位置信息编码进 attention。

---

## S

### Scheduler

vLLM 决定本轮哪些请求、多少 token 进入模型的调度器。

### SDMA

负责设备内存/共享内存数据搬运的 DMA engine。当前希望它能和 AI Core MM 并行。

### Signal

告诉 MemFabric/SDMA 发起当前 send slot 到 peer recv slot 的数据传输，并产生对应 mail 信息。

### Slot Mapping

把逻辑 token position 映射到 KV Cache 的实际物理槽位。

DFlash 一次扩多个 token 后尤其关键。

### Small-M Path

当前 `M < min(batch_m,256)` 时启用的专门 N-split 路径，用来避免大 batch padding 和完整权重流固定成本。

### Speculative Decoding

投机推理：便宜 draft 先猜多个 token，target 一次验证，尽量每轮接受多个 token。

### Stream

设备任务提交序列。异步 kernel/memcpy 通常 enqueue 到 stream，由依赖关系决定执行顺序。

---

## T

### T（small path template rows）

small-M N-split 使用的静态行模板：

```text
16,32,64,128,256
```

真实 M 向上匹配最近模板。

### Tail Batch

一波最后不足 `batch_m` 行的 batch。

当前只 copy `valid_rows` 到 once-zeroed scratch，padding 部分可以保留 stale 行，因为最终不 reduce 它们。

### Tensor Parallel / TP

把同一模型层的矩阵计算切给多个设备。

当前 MM+AR 只支持 TP=2。

### Tiling

把矩阵运算分成适合 AI Core/L1/UB/Cube 的块和循环方式。

当前 producer 典型基本块：

```text
baseN=256
baseK=64
```

### Token

模型处理的离散文本单位。一个汉字/单词不一定对应一个 token。

### TPOT

Time Per Output Token，平均每输出 token 时间。和 ITL 接近但统计定义可能不同，测试报告要明确口径。

### TTFT

Time To First Token，从请求发出到第一个输出 token 的时间。

---

## U

### UB

Unified Buffer，AI Core 上高速片上 buffer。AscendC vector/MM pipeline 常使用它做局部数据交换。

---

## V

### Vector Add

当前 local reduction 的设备向量加法：

```text
out = send + recv
```

由 `mf310pAddKernel` 实现。

---

## W

### W8A8

Weight 8-bit + Activation 8-bit 的量化策略统称。

重要：一个 W8A8 checkpoint 可以把少量敏感层排除在量化外。本项目目标 o_proj/out_proj 就是当前 FP16 例外。

### Wait

等待一封 peer SDMA mail，并校验 dst/len/imm。

它回答“我期待的 peer batch 到了吗”，不等于 quiet。

### Wave

一次安全占用 arena 的批次集合。

一个 wave 内可有多个 communication batch；wave 末尾 quiet + ack，下一 wave 通过 credit/gate 保证不会提前覆盖。

### Worker

vLLM 中管理一个设备/进程执行环境的组件。310P 有专门的 worker 实现。

---

## 常见易混淆对照

### Batch vs M

```text
batch = 服务/运行时的一组工作
M     = 当前矩阵实际输入行数
```

二者经常相关，但不等价。

### M-split vs Decode Split-K

```text
MMAR M-split：多个 AI Core 分 projection MM 的输出行
Decode Split-K：attention/decode 中围绕 K/历史序列维度拆分计算的另一类并行机制
```

不是一回事。

### single producer vs dedicated communication core

```text
single producer：只有 core0 发布 signal
```

不意味着：

```text
core0 不参与 MM
```

当前 core0 同样计算自己的 M/N 分片。

### AllReduce vs AllGather

```text
AllReduce：多个 rank 做 SUM/MAX 等 reduction，每边拿到 reduce 结果
AllGather：把各 rank 不同分片收集拼起来
```

当前 RowParallel 是 SUM AllReduce 语义。

### Fusion vs single kernel

```text
融合：减少执行边界/数据往返/同步并统一调度
```

不要求物理上只发射一个 kernel。

### Eager generation vs 文本 generation

完全不同。

```text
ready generation = 协议版本号
text generation  = 大模型生成 token
```

## 最后一个学习建议

遇到新术语，不要只查定义。最好立即补三句话：

```text
它在本项目哪里出现？
它保护/解决什么问题？
如果没有它会怎样？
```

只会说全称，不算理解；能把它放回数据流，才算真正掌握。
